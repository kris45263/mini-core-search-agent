# 测试方案

## 范围与判定原则

分别评估可确定的 harness 行为和非确定的模型回答质量。工程测试通过、API 正常退出或工具被调用，都不直接等于研究答案正确。

真实用例先确定应检查的事实，再运行；事实依据为对应版本的官方页面，不能将最新版的历史变更标记当成旧版页面已核实。每项标记为正确、部分正确、遗漏、错误或无法核实，不使用一个总分掩盖关键错误。

问题的精确原文和模式保存在 [cases.json](cases.json)。模型为测试时配置的 DeepSeek，普通与结构化模式使用同一模型；研究模式关闭隐藏 thinking，默认最多 12 次模型调用，Search basic 默认 3 条、可选 1–10 条及域名过滤，Extract basic，页面返回范围 24,000 字符。历史记录按当时配置解释。

## 当前版本真实用例

|ID|问题目标|检查点|预期和失败判据|
|---|---|---|---|
|simple|只回复你好|工具调用数量|可以直接回答，不应强制搜索/读取/think|
|page|读取 Python 3.13 memory 页面，核对 mimalloc 小节|准确 URL、续读、内容范围、结论|读到目标小节；不能把未记载说成现实中不存在，不能把片段说成全文|
|failure-retest|读取不存在的 example.com 路径，不替换来源|失败原因、是否额外搜索|报告已知失败事实，不编造正文；已知 404 不应丢成泛化失败|
|boundary|普通 GIL 与自由线程构建的捆绑/默认/必需条件|检索进展、版本来源、完整性、停止|区别三个维度，实际来源支持对应版本结论；无法核实时保留未确定项|
|note-free|读取 free-threading 页面后显式整理，再回答|笔记使用与最后结论|默认自由笔记实际执行；未记载与不存在分开|
|note-structured|与 note-free 相同问题|四个字段、操作引用、最终判断|结构合法且引用存在；结构正确不代表笔记内容正确|

`page` 等问题含指定 URL，验证的是读取/使用能力，不验证从零发现 URL 的能力。`boundary` 不提供具体 URL，观察自主发现和选择。笔记用例明确要求 think，只证明调用与格式可用，不证明自主选择或通用收益。

## 执行与记录

1. 独立 Session 运行每个用例，不向模型提供答案检查表。
2. 使用 `scripts/run_live_case.py --case ID --output 新文件.json` 运行。脚本拒绝覆盖已有结果。
3. 记录精确问题、模型、模式、调用次数、耗时、实际答案和操作摘要。当前脚本还保存返回的页面片段和实际搜索参数，机制探查数据可能包含完整提取文本，均属于测试时外部数据而非可信指令。不记录认证头或隐藏 reasoning 字段；发布前检查密钥与无关私人信息。
4. 人工对照官方原文和实际取得的片段/范围判断；正常退出只代表运行完成。脚本不会自动给答案打分。
5. 出现问题时先区分：搜索没取得、harness 处理丢失、读取范围不够、模型误读或来源归因错误。只改变与假设对应的变量。
6. 每个新假设先做小对照；少量重复只用于发现方向，不声称统计显著性或稳定成功率。

官方核对入口：

- [Python 3.13 内存管理](https://docs.python.org/3.13/c-api/memory.html)
- [Python 3.13 自由线程说明](https://docs.python.org/3.13/howto/free-threading-python.html)
- [Python 3.13 构建配置](https://docs.python.org/3.13/using/configure.html)
- [Python 3.13 发布变化](https://docs.python.org/3.13/whatsnew/3.13.html)

## 历史问题链与 A/B 方案

历史基线为 2026-09-07 当时的 snippet-only 版本，不是当前版本回归结果。实际问题与输出见 [历史实验数据](results/2026-09-07-experiments.json)。

|实验|问题/输入|唯一计划改变项|重复与边界|
|---|---|---|---|
|Q1→Q2→Q3 难度链|概览、自由线程限制、mimalloc 三个条件，各自独立会话|问题难度自然变化，不是严格 A/B|各一次，检查工具结果是否完整回传及最终引用|
|版本指令对照|Q3 最终回答前固定历史|系统提示词追加版本核实规则|原版/候选各两次，只看下一步模型输出|
|正文替换 A/B|Q3 第六次模型调用前，15 条消息|目标 tool.content：A 原搜索结果，B 实际指定页面正文并标注实验来源|各两次；前 14 条相同，经断言与哈希记录核对；正文长度和实验标签同时变化，不能隔离它们各自的影响|
|工具可用性 A/B|同一第六次模型请求前历史，模型此前自己已提出目标 URL|B 只多注册 read_page，不额外提供 URL|各两次，最多剩余 7 次模型调用；后续轨迹允许自然分叉，检验执行既有核查计划而非从零找链接|

工具实验首轮 B 因本机代理 DNS 被临时读取器误拦截，列为无效读取试验；修正官方域名读取后重新从相同原快照运行 B，不把失败历史混入重测。无效记录保留并标记，不计为“读到正文后仍失败”。

历史数据保留差异断言、输入前缀哈希、实际模型正文/工具调用及结果摘要；不是完整服务端状态快照。重新运行无法保证搜索结果或模型输出与历史一致。

## 工程测试覆盖

运行 `uv run python -X utf8 -m unittest discover -s tests -v`。工程测试全部使用假密钥与 MockTransport，不访问真实服务。

|文件|覆盖|
|---|---|
|test_agent.py|动态搜索、完整消息、多个调用配对、错误回传、正常结束/上限、显示一致性、配置来源|
|test_search_results.py|字段校验、整理、精确去重、空结果与全过滤区别|
|test_session.py|多输入继承、唯一系统提示词、成功提交、异常回退和清空|
|test_repl.py|连续输入、清空退出、失败/中断恢复、参数冲突|
|test_harness.py|读取和预算、分页、快照回退、失败状态、结构化引用|
|test_retrieval_edges.py|范围边界、刷新、报告 URL、畸形响应、原因映射、搜索状态、模式隔离、CLI 开关|
|test_deepseek_stream.py|真实增量回调、SSE/UTF-8 分片、终止条件、异常及连接释放|
|test_tool_stream.py|交错工具分片、收到 DONE 前不执行、断流不提交|
|test_stream_display.py / test_streaming_check.py|正文一次显示、flush、无工具追问、输入退出及输出故障|
|test_search_controls.py|数量/域名校验与透传、默认兼容、来源显示及控制字符遮蔽|

这些是明确边界的回归测试，不代表对所有网站、所有模型响应格式或事实正确性的穷尽证明。

## 当前轻量真实验收方式

先跑一次直接回答确认流式，再用 page 案例确认工具和续读；搜索控制用一个官网任务、一个多来源任务观察模型是否实际选择数量或域名。新问题优先做小规模真实案例，不以增加大量模拟测试代替观察。当前已执行结果与未验证事项统一记录在 [验收记录](../harness-validation.md)。
