## Seekra CLI 包装验收（2026-09-09）

代码迁移到 `src/seekra/`，新增 `seekra` 安装命令和 `python -m seekra` 入口；README 使用新的启动方式。CLI 默认读取当前工作目录的 `.env`，支持 `--env-file` 指定路径，统一处理 UTF-8，并增加欢迎信息、`› ` 提示符、`/help` 和 `--version`。

- `uv sync --locked` 后，70 项 unittest 通过，其中 5 项为安装入口测试；这些测试不访问真实服务。
- 独立临时工作目录验证帮助、版本、模块启动、REPL 本地命令、默认/显式配置；强制 `PYTHONUTF8=0` 和 `PYTHONIOENCODING=ascii` 后，中文输入输出仍通过。
- `uv build` 成功生成 wheel 和源码包。构建器提示缓存位于源码目录；实际检查两种归档，均未包含 `.env` 或 `.uv-cache`。
- 在项目内隔离的工具目录分别安装 wheel 和可编辑源码，验证裸命令的版本、帮助及 REPL 启动/退出。没有修改用户全局工具环境或持久 PATH。
- 对比迁移前后 7 个核心模块的语法树，除包导入路径外一致。现有依赖锁定版本保持不变，更新项目名和安装类型。
- 验收脚本的 `--list`、文档相对链接与代码围栏检查通过。历史 JSON 结果保持原样。

本次仅验证包装、安装及交互入口，没有重新调用真实模型或搜索服务，不增加新的答案质量结论。以下为之前阶段的记录。

日期：2026-09-08。研究模型使用本地配置的 `deepseek-v4-flash`；读取实现为 Tavily Extract basic，不使用网页摘要。没有保存密钥或认证头。

## 验收目标

1. 搜索与指定页面读取是独立能力，读页不会偷偷变成搜索。
2. 模型能看见搜索结果、成功/空/部分/失败状态，以及确切的模型调用预算。
3. 长页面可以续读同一提取快照；Session 消息与快照一起提交或回退。
4. 默认自由笔记保持可用；结构化笔记作为独立实验，不以结构通过代替语义正确。
5. 展示不改变决策输入，不重印系统提示词、隐藏推理或最终答案。

## 工程验证

2026-09-08 流式与检索控制版本：65 项 unittest 通过。覆盖 SSE 增量/工具拼接、Session 回退、来源显示、数量/域名参数及旧功能。真实模型/工具结果不由这个数字认证。

早期读取工具版本的 40 项测试通过记录如下，保留用于说明历史验证范围：

- 指定 URL 请求 Extract，状态和正文进入下一轮消息。
- 24,000 字符分页、尾部内容保留、后续读取不联网、快照一致。
- 超时、HTTP 失败、提取失败、空正文和非法响应分别返回。
- 参数错误和没有快照的续读不联网。
- 新读取失败不继续使用旧快照；Ctrl+C 传播。
- 整个研究失败时消息及页面同时回退；清空会话同时清空两者。
- 预算每轮准确，显示开关前后的实际请求一致。
- 结构化笔记字段及引用合法性，不将模型笔记当成外部证据。

## 真实验证与修复循环

直接 Extract 探针成功取得两个 Python 3.13 页面；一个不存在的 example.com 路径返回失败项，原因包含 404。

|场景|实际结果|判定|
|---|---|---|
|只回复你好|一次模型调用，无工具|简单问题未被强制执行研究流程|
|读取 3.13 memory 页面，判断 mimalloc 小节是否明确规定必须使用|自主读取并按 next_start 续读，3 次模型调用后区分“未记载”与“不存在”|获取、续读及局部证据判断通过；不是对所有回答的保证|
|读取不存在的页面，不改查其他页面|只调用 read_page，但第一次只收到泛化“提取失败”，模型猜测原因|未达预期：harness 丢失已知失败原因|
|修复后复测同一不存在页面|工具明确返回 provider 报告 404，模型准确报告失败且没有改查来源|错误事实反馈通过；不认证页面永久不存在|
|mimalloc 复杂版本问题，默认笔记|11 次模型调用后回答，读取了指定版本页面并识别版本文字差异|能力已使用，整体答案仅部分通过：仍有把未完全读完页面称为通读、以及文档解释扩大化的内容|
|同题，结构化模式|8 次模型调用后回答，没有调用 think|不能用于证明新笔记格式有效；仍有构建支持与运行时默认使用的语义混淆|
|读取 3.13 free-threading 页面后明确要求整理笔记，默认模式|调用 read_page 和 think，回答未记载不等于不存在|显式笔记实际可用|
|同一要求，结构化模式|调用 read_page，生成四个字段与 references，正常回答|真实协议与结构处理通过；本次 references 为空，不证明引用选择质量|

修复的是通用失败原因映射，不是 example.com 专用规则：provider 报告的 404、403、超时分别保留为受控原因；未知错误保持未知，不转储原始错误正文。补回归测试后重跑全部测试。

自由/结构化笔记真实对照各仅一次，搜索结果及模型输出具有随机性，不据耗时、次数或回答长度判定普遍收益。结构化模式因此默认关闭。

## 收敛范围和保留问题

工程目标及获取/状态功能收敛，已知可复现的信息损失已修复，未引入更多提示词补丁。复杂问题的事实推断仍不保证正确：页面读取成功不等于结论被核实，提取范围完整不等于网站完整；模型仍可能忽略这些区别。不能把这次修改称为修复了 mimalloc 问题或提升了通用事实正确率。
